# 04 · 新增 / 改造模块清单

> 本文档定义引入 ThoughtDAG 理念后需要实现的核心能力模块，明确每个模块的**职责边界**与**与其他模块的交互方式**。遵循"复用既有 Compose/Koin/Room，不引入重型库"的轻量化原则。

---

## 模块总览

```
┌───────────────────────────────────────────────────────────────┐

        │ GraphOrchestrator │◀── 状态机驱动 ──│ ContextAssembler │

        └───────┬───────┘                     └────────┬─────────┘
```

## M1 · GraphModel（DAG 核心模型）— 新增

**职责**
- 定义图的领域模型，解耦于现有 `UIMessage`：
  - `GraphNode(id, kind, sourceRef, label, state, position)`：`kind ∈ {MESSAGE, SOURCE, TOOL, REASONING}`；`sourceRef` 指向 `MessageNode.id` / 来源片段 / `Tool`；`position` 供画布布局。
  - `GraphEdge(id, from, to, type)`：`type ∈ {CONTEXT（上下文/父依赖）, SOURCE（来源溯源）}`。
  - `GraphContext`：一次"将要发给模型"的装配结果（含节点序列与 token 预算）。
- 提供 **拓扑遍历** 算法：`topoOrder(target) → 有序祖先序列`，并校验无环（写入时 `isAcyclic()`）。
- 提供 `MergeChunk` 式的图结构增量合并（用于流式构建图）。

**交互**
- 被 `ContextAssembler`（读取、遍历）与 `GraphOrchestrator`（写边/改状态）共同使用。
- 通过**映射器**与 `UIMessage`/`MessageNode` 互转，不侵入 `ai` 模块。

**关键约束**：无环校验、节点缓存避免重复遍历（`O(V+E)`）。

---

## M2 · ContextAssembler（上下文装配器）— 新增

**职责**
- 在 `GenerationHandler` 组装请求序列处（挂点②）注入。
- 输入：目标 `GraphNode` + 全图 + 既有 `MessageNode` 选中版本。
- 行为：拓扑遍历入边 → 按拓扑序收集祖先选中版本 → 产出 `GraphContext`（发送给 `provider.streamText` 的 `List<UIMessage>`）。
- 计算 **token 预算与预览**：用既有 `MessageNodeDAO.getTokenStats()` 逻辑/估算，输出 `ContextPreview`（节点清单、总 token、与上一版 diff）。

**交互**
- 上游：被 `GenerationHandler` 调用（替代直接读 `currentMessages`）。
- 下游：产出 `GraphContext` 交给 `Provider`；产出 `ContextPreview` 交给 UI（Inspect/Diff 展示）。
- 可注册为 **InputMessageTransformer**（挂点③）以复用管线时序。

**关键约束**：保留"无图模式"回退（直接返回现有 `currentMessages`），保证向后兼容。

---

## M3 · GraphOrchestrator（编排执行器）— 新增

**职责**
- 基于 DAG 的**轻量任务编排器**，驱动 ThoughtDAG 四大操作：
  - **Branch**：复制/新增 `GraphNode` 与分支边，复用 `MessageNode.messages[selectIndex]` 切换机制。
  - **Prune**：移除一条 `CONTEXT`/`SOURCE` 边（不删节点数据，仅改变上下文构成）→ 触发上下文重算。
  - **Merge**：将若干节点的产出合并为新节点（选定策略：last/first/concat）。
  - **Inspect**：调用 `ContextAssembler` 预览，不发起真实请求。
- 状态机：`PENDING → READY → RUNNING → DONE / PRUNED`，按拓扑依赖推进（复用 `GenerationHandler` 的 `maxSteps` 循环与 `Tool` 执行内核）。

**交互**
- 操作来源：UI 画布手势（`GraphCanvas`）与气泡内快捷操作（`ChatMessageBranch`）。
- 执行后端：复用现有 `Tool` 执行与结果回填机制，不产生新执行引擎。

**关键约束**：编排不阻塞 UI（在 ViewModel 协程 + Flow 中推进状态）。

---

## M4 · GraphCanvas（可视化画布）— 新增 UI

**职责**
- 可拖拽、可缩放、可连线的 DAG 画布：
  - 节点 = `GraphNode`（消息/来源/工具/推理），以卡片呈现其摘要。
  - 边 = `GraphEdge`（上下文依赖 / 来源溯源），以有向连线呈现。
  - 手势：`pointerInput` 实现平移（双指/拖背景）、缩放（捏合）、节点拖拽、从节点拉出新边。
- 提供 Inspect 浮层：展示 `ContextPreview`（token 数、节点清单、与当前上下文的 diff：删除一条边显示 `−N tokens`）。
- 提供 Branch/Prune/Merge 的画布内操作菜单。

**交互**
- 数据来自 `GraphCanvasVM`（经 `GraphStore` 读取 `GraphModel`）。
- 操作意图回传 `GraphOrchestrator`。
- **不使用 WebView/mermaid**（交互不足）；mermaid 仅用于"导出 PNG/分享"（P2，经 `web` 模块或 `Mermaid.kt`）。

**关键约束**：纯 Compose `Canvas` + 自绘 + `pointerInput`，零新增图形库（保证 <0.5MB 增量）。

---

## M5 · GraphStore / GraphDAO（持久化）— 新增

**职责**
- 新增 Room 实体与 DAO，承载图的边与节点布局：
  - `GraphNodeEntity(conversationId, nodeId, kind, sourceRef, label, state, x, y)`。
  - `GraphEdgeEntity(conversationId, edgeId, from, to, type)`。
- 接口遵循既有 `ConversationDAO`/`MessageNodeDAO` 模式：`Flow<List<...>>` / `suspend` / `RawQuery`（token 统计复用 `json_each`）。
- `AppDatabase` 升 version 并新增迁移（保留旧 `message_node` 表）。

**交互**
- 被 `GraphOrchestrator`（写）与 `GraphCanvasVM`（读）使用。
- 与现有 `ConversationRepository` 协同：图与 `Conversation.messageNodes` 通过 `sourceRef` 关联，旧数据无需迁移即可"无图模式"运行。

**关键约束**：图数据可独立查询/分页，不影响现有对话读写性能。

---

## M6 · GraphCanvasVM + DI 注册 — 新增（粘合层）

**职责**
- `GraphCanvasVM(conversationId)`：持有 `GraphModel` 的 UI 状态（`Flow`）、缓存画布布局、暴露操作意图给 `GraphOrchestrator`。
- 在 `app/.../di/` 新增 `GraphModule`（Koin `module { }`），声明 `GraphOrchestrator`、`ContextAssembler`、`GraphStore` 为 `single`/`factory`。

**交互**：标准 Koin + ViewModel 模式，与 `ViewModelModule` 风格一致。

## 模块职责速查表

| 模块 | 类型 | 必改 | 主要交互对象 | 新增依赖 |
|---|---|---|---|---|
| M1 GraphModel | 领域模型（app） | 是 | Assembler、Orchestrator、Store | 无 |
| M2 ContextAssembler | 服务/Transformer | 是 | GenerationHandler、Provider | 无 |
| M3 GraphOrchestrator | 服务 | 是 | CanvasVM、Tool 内核 | 无 |
| M4 GraphCanvas | Compose UI | 是 | CanvasVM、Orchestrator | 无（自绘） |
| M5 GraphStore/DAO | Room | 是 | Orchestrator、CanvasVM | Room（已有） |
| M6 GraphCanvasVM+DI | 粘合 | 是 | 以上全部 | Koin（已有） |

> 所有模块均落在 `app` 模块内，复用既有 Compose / Koin / Room / Provider / Tool 内核，**不新增外部库**，从而满足"轻量化部署"。
