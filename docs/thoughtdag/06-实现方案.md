# 06 · 实现方案

> 本文档给出每个模块的实现思路、关键步骤与涉及的文件/目录，并明确"轻量化部署"约束（复用 Compose/Koin/Room，画布轻量自绘，不引入重型库）。所有代码路径基于真实仓库结构，可直接作为后续实现蓝图。

---

## 0. 轻量化部署约束（贯穿全局）

| 约束 | 说明 |
|---|---|
| 不引入图形库 | 画布用 Compose `Canvas` + `pointerInput` 自绘，避免 +1~3MB 的图形库 |
| 不引入新 native 库 | 复用现有 MNN/workspace 原生，图功能纯 Kotlin |
| 复用既有基础设施 | Koin（`di/`）、Room（`data/db`）、Compose 主题、Provider 抽象、Transformer 管线 |
| 向后兼容 | 保留 `currentMessages` 作为"无图模式"，旧对话无需迁移即可运行 |
| 画布入口可选 | 默认关闭图谱模式（设置开关），普通用户零负担 |

**包体积影响**：预计增量 < 0.5MB（仅新增 DEX）。详见总索引 README 的"包体积分析"。

## 1. M1 GraphModel — 实现方案

**目标文件（新增）**
- `app/src/main/java/com/ninef/rikkallm/data/graph/model/GraphModel.kt`
  - `enum class GraphNodeKind { MESSAGE, SOURCE, TOOL, REASONING }`
  - `enum class GraphEdgeType { CONTEXT, SOURCE }`
  - `data class GraphNode(val id, val conversationId, val kind, val sourceRef, val label, val state, val x, val y)`
  - `data class GraphEdge(val id, val conversationId, val from, val to, val type)`
  - `data class GraphContext(val nodes: List<Uuid>, val messages: List<UIMessage>, val tokenEstimate: Int)`

**关键算法**
- 拓扑遍历 `topoOrder(target: Uuid): List<Uuid>`：以 `edges` 构建邻接表（CONTEXT 边为父依赖），从 `target` 反向 BFS/DFS 收集祖先，按 Kahn 拓扑序排序后输出。缓存结果（`Map<Uuid, List<Uuid>>`）避免重复。
- 无环校验 `isAcyclic()`：在 `addEdge` 时执行 DFS 着色（白/灰/黑），若发现回边则拒绝。

**映射器（新增）**
- `app/.../data/graph/model/GraphMappers.kt`
  - `MessageNode.toGraphNode()` / `GraphNode.toMessageNodeRef()`，仅传引用不复制消息体。

**关键步骤**
1. 定义领域类与枚举。
2. 实现 `topoOrder` / `isAcyclic`（带缓存）。
3. 实现与 `UIMessage`/`MessageNode` 的映射器。
4. 单元测试：环检测、拓扑序、缓存命中（参考 `ai/src/test/.../GenerativeCardTest.kt` 的测试风格）。

## 2. M2 ContextAssembler — 实现方案

**目标文件（新增）**
- `app/src/main/java/com/ninef/rikkallm/data/ai/graph/ContextAssembler.kt`
  - `suspend fun assemble(conversationId, targetNodeId, graph): GraphContext`
  - `suspend fun preview(conversationId, targetNodeId, graph): ContextPreview`

**关键步骤**
1. 读取 `Conversation`（含 `messageNodes`）与 `GraphModel`（边 + 选中版本）。
2. 调 `GraphModel.topoOrder(target)` 得到祖先顺序。
3. 对每个祖先取 `messageNodes[selectIndex]` 的 `UIMessage`，拼成 `List<UIMessage>`。
4. token 估算：复用 `MessageNodeDAO.getTokenStats()` 的 JSON 展开统计逻辑，或调用模型 tokenizer（P1）。
5. `ContextPreview` 记录节点清单、总 token、以及与"上一版上下文"的差异（增/删边 → `+N / −N tokens`）。
6. **无图模式回退**：当 `graph` 为空/未启用时，直接返回 `conversation.currentMessages`。

**与挂点②集成（改造）**
- 在 `app/.../data/ai/GenerationHandler.kt` 的 `generateText(...)` 组装请求处，将 `conversation.currentMessages` 替换为：
  ```kotlin
  val ctx = contextAssembler.assemble(conv.id, targetNodeId, graph)
  provider.streamText(ctx.messages, params)
  ```
- 可选：将 `ContextAssembler` 包装为 `InputMessageTransformer`，注入 `List<UIMessage>.transforms(...)` 管线（挂点③）。

## 3. M3 GraphOrchestrator — 实现方案

**目标文件（新增）**
- `app/src/main/java/com/ninef/rikkallm/data/graph/GraphOrchestrator.kt`

**状态机**
```kotlin
enum class NodeState { PENDING, READY, RUNNING, DONE, PRUNED }
```

**四大操作实现**
- **Branch**：在 `MessageNode.messages` 末尾追加新版本（或新增并行 `GraphNode` + 一条 CONTEXT 边）；复用 `ChatMessageBranchSelector` 的 `selectIndex` 切换体验。
- **Prune**：仅 `graphStore.removeEdge(edgeId)`，节点数据保留；随后重算 `ContextAssembler.preview` 并刷新 UI（体现"删边 −N tokens"）。
- **Merge**：将多个 `GraphNode` 的 `UIMessage` 按策略（last/first/concat）合并为新 `GraphNode` + 汇聚边。
- **Inspect**：调用 `ContextAssembler.preview(...)`，不调用 `provider`，仅向 UI 推送 `ContextPreview`。

**执行内核复用**
- 多步编排直接复用 `GenerationHandler.generateText` 的 `for (stepIndex in 0 until maxSteps)` 循环与 `Tool` 执行/回填机制；编排器负责"按拓扑推进状态"，生成器负责"执行单步"。

**关键步骤**
1. 实现状态机与拓扑推进。
2. 实现 Branch/Prune/Merge/Inspect。
3. 在 ViewModel 协程 + `Flow` 中发布状态（不阻塞 UI）。

## 4. M4 GraphCanvas — 实现方案

**目标文件（新增）**
- `app/src/main/java/com/ninef/rikkallm/ui/pages/graph/GraphCanvasPage.kt`（路由页）
- `app/.../ui/components/graph/GraphCanvas.kt`（自绘画布组件）
- `app/.../ui/components/graph/GraphNodeCard.kt`（节点卡片）
- `app/.../ui/components/graph/GraphEdgeLayer.kt`（连线绘制）

**关键步骤**
1. **布局**：用 `Canvas(modifier.fillMaxSize())` 绘制；维护 `Offset` 平移与 `Float` 缩放状态（`graphViewModel` 持有，避免重组抖动）。
2. **节点绘制**：`GraphNodeCard` 以 `Box`/`Card` 叠加在 Canvas 之上（或纯 Canvas 绘制圆角矩形 + 文本），位置 = `node.x/y * scale + pan`。
3. **手势（`pointerInput`）**：
   - 背景拖动 → 平移；双指捏合 → 缩放。
   - 节点 `detectDragGestures` → 更新 `node.position` 并落库（M5）。
   - 连线：在某节点边缘 `pointerInput` 中按下并拖动到目标节点释放 → 调 `GraphOrchestrator` 新增 `GraphEdge`。
4. **Inspect 浮层**：点击节点/边 → 弹出 `ContextPreview`（token、清单、删边 `−N tokens`）。
5. **菜单**：长按节点 → Branch/Prune/Merge 操作（调 M3）。
6. **导出（P2）**：经 `app/.../ui/components/richtext/Mermaid.kt` 的 WebView 将图序列化为 Mermaid 文本预览/PNG。

**轻量化要点**：全程 Compose 原语，无 WebView（交互画布）、无第三方图形库。

**实体**
```kotlin
@Entity(primaryKeys = ["conversationId","nodeId"])
data class GraphNodeEntity(
    val conversationId: String, val nodeId: String,
    val kind: String, val sourceRef: String,
    val label: String, val state: String,
    val x: Float, val y: Float,
)

@Entity(primaryKeys = ["conversationId","edgeId"])
data class GraphEdgeEntity(
    val conversationId: String, val edgeId: String,
    val fromNode: String, val toNode: String, val type: String,

```

**DAO（遵循 `MessageNodeDAO` 模式：Flow / suspend / RawQuery）**
```kotlin
@Dao interface GraphDAO {
    @Query("SELECT * FROM GraphNodeEntity WHERE conversationId = :cid")

    @Query("SELECT * FROM GraphEdgeEntity WHERE conversationId = :cid")
    fun getEdgesFlow(cid: String): Flow<List<GraphEdgeEntity>>
    @Upsert suspend fun upsertNode(e: GraphNodeEntity)
    @Upsert suspend fun upsertEdge(e: GraphEdgeEntity)
    @Query("DELETE FROM GraphEdgeEntity WHERE edgeId = :id")
    suspend fun removeEdge(id: String)
    @RawQuery suspend fun tokenStats(query: SupportSQLiteQuery): ... // 复用 json_each
}
```

**迁移**
- `AppDatabase` 升 `version`，在 `@Database` 的 `autoMigrations` 或 `addMigrations` 中新增迁移，仅新增两张表，**保留旧 `message_node` 表**（向后兼容）。
