# 02 · 数据流说明

> 本文档描述 RikkaLLM 中"一次用户发言 → 模型响应 → 落库 → 展示"的完整链路，标注关键数据结构与接口，为"在何处插入 DAG 上下文装配"提供精确坐标。

---

## 1. 端到端链路

```
[用户输入]  ChatPage.kt (输入框)
    │  vm.handleMessageSend(contents)
    ▼
[ViewModel] ChatVM（com.ninef.rikkallm.ui.pages.chat）
    │  组装 UIMessage(USER) → 更新 Conversation.messageNodes
    ▼
[持久化]  ConversationRepository → ConversationDAO.update(entity)
    │  （nodes 以 JSON 列式存储）
    ▼
[编排/生成] GenerationHandler.generateText(settings, model, messages, assistant, ...)
    │  循环 step ∈ [0, maxSteps)：
    │    ① 构建工具清单 buildTools(assistant)
    │    ② 组装请求序列  ── 当前：conversation.currentMessages
    │    ③ 应用 InputTransformer 管线
    │    ④ provider.streamText(messages, params) → Flow<MessageChunk>
    │    ⑤ 流式 merge 到 UIMessage（mergeChunk）
    │    ⑥ 应用 OutputTransformer 管线（.transforms(...)）
    │    ⑦ 工具调用回环：执行 Tool，回填 ToolResult，继续
    ▼
[Provider] OpenAIProvider/GoogleProvider/ClaudeProvider/LocalServerProvider
    │  SSE/HTTP → MessageChunk 流
    ▼
[回写]  更新 MessageNode（assistant 消息），落库 MessageNodeDAO
    ▼
[UI 刷新]  ChatPage 收集 Flow → 重组消息列表（LazyColumn）
```

## 2. 关键数据结构

### 2.1 Conversation / MessageNode（对话树）
`app/.../data/model/Conversation.kt`

```kotlin
@Serializable
data class Conversation(
    val id: Uuid,
    val assistantId: Uuid,
    val messageNodes: List<MessageNode>,   // 分叉式节点列表（现状为线性有序）
    val customSystemPrompt: String? = null,
    val modeInjectionIds: Set<Uuid> = emptySet(),
    val lorebookIds: Set<Uuid> = emptySet(),
    val workspaceCwd: String? = null,
    ...
) {
    // 当前发给模型的序列：每个节点取“选中版本”
    val currentMessages: List<UIMessage>
        get() = messageNodes.map { it.messages[it.selectIndex] }
}

@Serializable
data class MessageNode(
    val id: Uuid,
    val messages: List<UIMessage>, // 同一节点的多个重生成版本
    val selectIndex: Int = 0,       // 当前选中版本
    @Transient val isFavorite: Boolean = false,
)
```

> **关键观察**：`currentMessages` 是**唯一**的"上下文序列"计算点。现状它按节点顺序、各取一个选中版本，形成线性序列。DAG 改造的核心即：**用"遍历图入边得到的祖先序列"替换这一线性映射**。

### 2.2 UIMessage / UIMessagePart（消息体）
`ai/src/main/java/me/rerere/ai/ui/Message.kt`、`UIMessagePart.kt`

```kotlin
data class UIMessage(
    val id: Uuid,
    val role: MessageRole,                // USER / ASSISTANT / SYSTEM / TOOL
    val parts: List<UIMessagePart>,
    val annotations: List<UIMessageAnnotation> = emptyList(),
    val createdAt: LocalDateTime,
    val finishedAt: LocalDateTime? = null,
    val modelId: Uuid? = null,
)

sealed class UIMessagePart {
    data class Text(val text: String, ...)
    data class Image(val url: String, ...)
    data class Video(val url: String, ...)
    data class Audio(val url: String, ...)
    data class Document(val url: String, val fileName: String, val mime: String, ...)
    data class Reasoning(val reasoning: String, ...)
    data class Tool(            // 工具调用（含执行结果）
        val toolCallId: String, val toolName: String,
        val input: String, val output: List<UIMessagePart> = emptyList(),
        val approvalState: ToolApprovalState = ToolApprovalState.Auto, ...
    )
    data class GenerativeCard(val card: GenerativeCardData, ...)  // 生成式 UI
}
```

流式更新通过 `UIMessage.mergeChunk(...)` 将增量 chunk 合并进现有消息（文本追加、Reasoning 追加、`Tool` 合并等）。

## 3. 持久化流向

- **写入**：`ChatVM` → `ConversationRepository` → `ConversationDAO.update(ConversationEntity)`。实体以 `nodes` JSON 列存放 `messageNodes`；细粒度 `message_node` 表经 `MessageNodeDAO` 操作，`messages` 同样为 JSON 列。
- **读取**：`ConversationDAO.getConversationFlowById(id): Flow<ConversationEntity?>` 驱动 UI 实时刷新；列表页用 `PagingSource`。
- **统计**：`MessageNodeDAO` 用 `json_each()` 展开 `messages` JSON，聚合 token（`getTokenStats()`），可作为"上下文预览"的现有基础。

## 4. 数据流中的扩展挂点（摘要，详见 03）

| 挂点 | 位置 | 用途 |
|---|---|---|
| **① 上下文序列计算** | `Conversation.currentMessages` | 替换为 DAG 遍历结果（核心） |
| **② 装配前 hook** | `GenerationHandler` 组装请求处 | 插入 `ContextAssembler` |
| **③ Transformer 管线** | `List<UIMessage>.transforms(...)` | 新增上下文装配/溯源 transformer |
| **④ 工具回环** | `GenerationHandler` step 循环 | 编排器可驱动多节点依赖 |
| **⑤ 持久化** | `ConversationEntity` / `MessageNodeDAO` | 新增图实体与边表 |
| **⑥ UI** | `ChatPage` + `ChatMessageBranch` | 新增画布入口与 Branch/Prune/Inspect 交互 |
